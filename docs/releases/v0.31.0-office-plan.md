## Scope

1. **MCPWP office addon, slices 1–2** (mupot#1580).
   - Slice 1 (T1) — PR #1582 (`flight/office-addon-s1`, head `3915a7f3`, base
     `main` `681e2dab`), **open, not merged**. Delivers the
     `mcpwp-office` `AddonManifestV1` ("WordPress as each pot's office"):
     `kind: 'external_mcp'`, `trustClass: 'external_isolated'`, a required
     `office` department, a `site-operator` agent template/squad, one
     `wordpress_site` connector requirement (accepts `mcpwp`, required,
     write, vault-scoped), and `authorityRequests.surfaceGrants` naming three
     office tools for slice 2 to implement:
     `office.publish_post`, `office.list_pending_approvals`,
     `office.review_approval`. Health check
     (`src/addons/office/health.ts`) does one SSRF-guarded JSON-RPC
     `initialize` probe against `<site>/wp-json/mcpwp/v1/mcp`.
   - **Known blocker surfaced by slice 1, not fixed there:**
     `src/addons/service.ts`'s `installAddon` hard-refuses any manifest that
     is not exactly `(kind: 'native', trustClass: 'native_reviewed')` —
     `addon_installations` and `addon_receipts` both carry a SQL `CHECK
     (trust_class = 'native_reviewed')` at the schema level
     (`migrations/0050_addons.sql`). This addon (`kind: 'external_mcp'`)
     cannot be installed/disabled/archived through the real lifecycle today.
     This is a schema-migration and trust-boundary decision — Athena's/
     Kasra-core's call, not a builder's to route around. Slice 2 needs this
     resolved (or explicitly deferred) before it can run the three office
     tools under a real installed/active installation row.
   - Slice 2 (T2) — not started as of this writing: implement
     `office.publish_post`, `office.list_pending_approvals`,
     `office.review_approval` against the manifest slice 1 shipped.
2. **Auth residuals** (mupot#1583, PR #1583, `flight/auth-residuals`,
   **open, not merged**). `/api/projects` authority becomes the session
   member (`sessionMemberId`), never re-resolved from email; resolver step 4
   (`owner_login_emails`) removed as dead and dangerous; `findUserByEmail`
   fails closed on case-variant collisions; CI ratchet
   `check-member-email-authority-lookup` (allowlist per-file counts); `tests/
   auth-dev-login` rewritten onto the real SQLite harness. See
   [docs/security-model.md](../security-model.md) "Login Identity Attach:
   Exclusive Control" for the surrounding predicate this closes a residual
   gap next to.
3. **Tag `v0.31.0`** once both land, CI is green, and the release gate
   passes. No tag exists yet — do not claim one does.
